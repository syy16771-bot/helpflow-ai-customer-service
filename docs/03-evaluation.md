# 正式评测方案与结果

## 评测目标

评测不使用模型自动判分，而是将实际回答与预期要点逐条人工核对。重点检查：

- 回答是否符合产品规则。
- 是否使用了正确知识，是否出现无依据补充。
- 应拒答问题是否正确拒答。
- 权限、退款和敏感信息是否安全处理。
- 多轮上下文与模糊指代是否理解正确。
- 回答是否简洁、自然。

## 测试设计

正式测试共 50 条，覆盖正常 FAQ、权限、退款、数据操作、模糊问题、多轮追问、知识外问题、诱导编造、敏感信息和错误前提。

执行流程：

```text
固定测试集 → 批量执行 → 收集原始回答与耗时 → 人工评分
→ 失败分类 → Trace 定位 → 单题回归 → Full 全量回归
```

多轮测试在同一会话内依次执行，其他测试使用独立会话，避免上下文相互污染。公开仓库仅提供代表性测试样例，不公开完整 50 条及原始回答明细。

## 最终结果

| 指标 | 结果 | 含义 |
| --- | ---: | --- |
| 正式测试 | 50 条 | 全部取得有效回答 |
| 业务正确性 | **50/50（100%）** | Full 与同版本 single 结果合并后，逐条符合预期要点 |
| Full 一次性端到端成功率 | **46/50（92%）** | 一次 Full 中在本地等待时限内完成的测试比例 |
| 业务逻辑失败 | **0** | 当前固定测试集未发现回答逻辑 Fail |

这些测试没有在 Full 中一次完成，因此不能提高 92% 的端到端成功率；但 single 回归证明其业务回答正确，因此不计为业务逻辑失败。

## 如何解读结果

- **100% 业务正确性**回答“系统最终答得对不对”。
- **92% 一次性端到端成功率**回答“系统能否在一次批量运行中稳定完成”。
- 两项指标不能合并，也不能用 single 回归覆盖 Full 的原始超时。
- 当前主要风险是免费模型服务或 Dify 上游的延迟波动与偶发超时。

## 评测边界

50/50 是固定测试集上的 Demo 结果，不代表真实用户分布或生产环境可用性。项目尚未验证峰值并发、长期监控、企业权限隔离和大规模知识更新。
