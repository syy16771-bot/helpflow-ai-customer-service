# 项目概览

## 项目定位

HelpFlow AI 智能客服是一个面向 AI 产品岗位的个人作品集 Demo。项目以虚构 SaaS 客户管理产品为背景，验证 FAQ 路由、多轮上下文、模糊问题澄清、无依据拒答和敏感信息保护能力。

## 用户问题

- 账号、套餐、退款、发票、权限和数据操作等问题高频重复。
- 人工逐条回答成本较高，不同人员的业务口径可能不一致。
- AI 若猜测价格、退款或权限规则，会带来业务和安全风险。
- 用户表达可能包含“这个”“他”“那年付呢”等指代或省略，需要结合上下文判断是否承接或澄清。

## 产品目标

1. 用统一 FAQ 覆盖高频咨询，降低重复回答成本。
2. 只依据确定规则回答，知识不足时不编造。
3. 对模糊问题主动澄清，对敏感信息和不可代办事项保持安全边界。
4. 用固定测试和 Trace 建立可解释、可回归的产品迭代流程。

## 方案选择

当前知识规模为 28 条 FAQ。项目曾考虑混合检索和全文检索，但免费资源限制与中文召回错排会影响成本和可控性，因此最终采用 Router → Lookup → Answer LLM 三层方案：

- Router 只判断最相关 FAQ，不直接生成业务答案。
- Lookup 按 FAQ ID 读取确定规则，避免模型自行补充产品事实。
- Answer LLM 负责自然表达、多轮承接、模糊澄清和安全回答。

这一方案适合小规模作品集 MVP：结构清晰、规则可查、问题易定位。它不被包装为大规模生产知识系统。

## 我的工作

- 定义目标用户、咨询场景、产品边界和精简 PRD。
- 编写一致的产品规则并整理 28 条结构化 FAQ。
- 设计 AI 应用结构与 Answer Prompt 安全约束。
- 设计 50 条正式测试及人工评分维度。
- 搭建批量执行和回归流程，收集回答、状态与耗时。
- 通过 Trace 定位代表性失败，完成最小修改和全量回归。

## 最终结果

| 指标 | 结果 |
| --- | ---: |
| 正式测试 | 50 条 |
| 业务正确性 | 50/50（100%） |
| Full 一次性端到端成功率 | 46/50（92%） |
| 业务逻辑失败 | 0 |

四条 Full 超时在 single 回归中均成功。业务回答达到 Demo 目标，主要遗留风险是免费模型服务或 Dify 上游的延迟波动与偶发超时。

> HelpFlow 的品牌、价格、联系邮箱、业务规则和测试数据均为虚构演示内容。
